## 0. Context in one paragraph

Owner device finding F2 (2026-11-14, `docs/UX_BACKLOG.md`): the Driver
Card for a Tanzania venue never prefers Swahili. Root cause, verified on
main: `languagePriority` in
`mobile/lib/features/driver_card/driver_card_helpers.dart` handles Laos
(`lo`, `th`, `en`) and Dubai (`ar`, `en`) only; every other region,
including `zanzibar_tanzania` and `nungwi_tanzania`, falls back to
`['en']`. The seed side already maps both Tanzania regions to `sw`
(`REGION_LANGUAGES` in `scripts/load_venues.py`, `CATALOG_LANGUAGES` in
`seed_data.py`). The client mirror is missing, and nothing guards the
two sides against drifting apart. This slice adds the client mirror and
a guard. It does not add Swahili names or landmark data (that is an
owner-verified data pass, later).

## 1. Goal and the properties that matter

1. `languagePriority('zanzibar_tanzania')` and
   `languagePriority('nungwi_tanzania')` return `['sw', 'en']`.
2. Laos, Dubai, and unknown regions return exactly what they return
   today.
3. A Python guard test proves that, for every region in
   `REGION_LANGUAGES`, the first language the Dart client prefers equals
   the loader's language for that region. Today that guard would fail
   for both Tanzania regions; after this slice it passes. Adding a new
   region to `REGION_LANGUAGES` without a client rule must make it fail.
4. SPEC-12 provenance rules are unchanged: a `generated` Swahili name
   still renders as the ask tier with the confirm affordance; only
   verified sources render as the confident headline.

## 5. The change

ASCII only.

### 5.1 Dart

In `languagePriority`, add one rule after the Dubai rule:

    if (region.contains('tanzania')) return const ['sw', 'en'];

Keep the doc comment; extend it with one line saying the list mirrors
`REGION_LANGUAGES` in `scripts/load_venues.py` and a Python test keeps
them in step.

### 5.2 Dart test: `driver_card_tanzania_test.dart`

Exact test names:

1. `tanzania regions prefer swahili then english`
   Both region codes return `['sw', 'en']`.
2. `laos dubai and unknown regions are unchanged`
   `luang_prabang_laos` -> `['lo', 'th', 'en']`, `dubai_uae` ->
   `['ar', 'en']`, `null` and `'paris_france'` -> `['en']`.
3. `swahili entry is chosen over english for a tanzania venue`
   `resolvePreferredLocalEntry` on a map with both `sw` and `en`
   entries (non-empty `value`) for `nungwi_tanzania` returns the `sw`
   entry.
4. `english is used when swahili is missing`
   Same with only `en` present returns the `en` entry.
5. `generated swahili name stays in the ask tier`
   `tierForNameSource('generated')` is `FactTier.ask` and
   `tierForNameSource('field_verified')` is `FactTier.assert_`
   (documents that F2 does not loosen SPEC-12).

### 5.3 Python guard: `tests/test_f2_driver_card_language_priority.py`

No Flutter needed. Read the Dart file as text and parse the ordered
rules inside `languagePriority` with a small regex over lines of the
form `if (region.contains('<needle>')) return const [<langs>];` plus the
final `return const [<langs>];` fallback. Resolve a region by walking
the rules in order (first `needle in region.lower()` wins, else the
fallback), the same way the Dart does.

Exact test names:

1. `test_parser_reads_the_expected_rules`
   The parsed rule list contains the `laos`, `dubai` and `tanzania`
   needles in that order and an `['en']` fallback. This keeps the
   parser honest: if it silently parses nothing, this fails.
2. `test_client_first_language_matches_loader_for_every_region`
   For every region in `scripts.load_venues.REGION_LANGUAGES`, the first
   language the parsed Dart rules return equals the loader language.
3. `test_tanzania_regions_resolve_to_swahili_then_english`
4. `test_unknown_region_falls_back_to_english`
5. `test_driver_card_helpers_is_ascii`
